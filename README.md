# Arkanoid

Классический Arkanoid по мотивам Famicom 1986. Сделал на чистом HTML5 + CSS3 + JavaScript, рендеринг через PixiJS v8, звук — Web Audio API. Без сборщиков, без npm, без сторонних библиотек кроме Pixi.

## Что получилось

Играбельный арканоид: ракетка, мяч, сетка блоков 10×6, счёт, три жизни, состояния MENU / PLAYING / PAUSED / GAME_OVER / VICTORY. Верхние два ряда блоков бронированные — выдерживают два удара. Есть пауза по Esc, рестарт по пробелу, победа при зачистке поля.

Всё это — в одном классе `ArkanoidGame`, с методом `destroy()` для полной выгрузки. Снаружи в глобальной области ничего не висит.

## Соответствие ТЗ

- HTML, CSS, JS — в разных файлах.
- PixiJS — весь игровой мир и HUD рисуются через него.
- Изоляция — класс `ArkanoidGame`, никаких глобальных функций.
- Внешний вид — ретро-палитра, шрифт Press Start 2P, свечение рамки, HUD в углах.
- Анимации — разрушение блока, тряска экрана, вспышка блока hp:2.
- Близко к референсу — угол отскока зависит от точки удара по ракетке, блоки hp:2, разгон мяча.
- Десктоп — фиксированный canvas 800×600, без адаптива.
- Бонусы — анимации и экран меню с правилами.
- Коммиты — 14 штук, по одному на каждый логический шаг.

## Как устроено

```
ArkanoidGame
 ├── world (слой) — ракетка, мяч, блоки
 └── hud (слой)   — очки, жизни, уровень
```

Каждый кадр `ticker` вызывает `update()`. Порядок:

1. Обновляются эффекты (умирающие блоки, тряска).
2. Если состояние не PLAYING — обрабатываются клавиши и выход.
3. Двигаются ракетка и мяч.
4. `CollisionSystem` проверяет: мяч ↔ стены → ракетка → блоки.
5. При попадании в блок — анимация, счёт, звук.
6. Проверка победы.

Коллизии со стенами, ракеткой и блоками — в одном месте, в `CollisionSystem`. Ракетка не знает про мяч, мяч не знает про блоки. Все пересечения считает система.

Сторона удара по блоку определяется через **penetration depth** — сравниваем, по какой оси пересечение меньше, туда и отбиваем. Это решает проблему залипания мяча в углах между блоками. Без этого классический баг: мяч попадает в стык двух блоков и дёргается.

Угол отскока от ракетки: считаем, где мяч ударил относительно центра — от −1 (левый край) до +1 (правый). Умножаем на 60°. По центру — прямо вверх, по краю — почти горизонтально.

Скорость мяча растёт после каждого блока, но не больше `MAX_SPEED = 11`. Потолок нужен, потому что при 60 FPS мяч со скоростью >16 px/кадр начинает пролетать сквозь ракетку за один кадр. 11 — с запасом.

## Стек

- PixiJS 8 — рендеринг, граф сцены, ticker.
- Web Audio API — звуки генерируются программно, файлов нет.
- ES6 modules — `import`/`export`, без сборщика.
- Importmap — Pixi подключается с CDN.

Кроме Pixi ничего не подключал.

## Запуск

Нужен HTTP-сервер — ES-модули и importmap не работают через `file://`.

**Live Server в VS Code:** правый клик по `index.html` → Open with Live Server.

**Через Python:**
```
python3 -m http.server 8080
```
Открыть `http://localhost:8080`.

**Управление:** стрелки или A/D — ракетка, SPACE — старт/рестарт, ESC — пауза.

## Как это выглядит в коде

```
js/
├── main.js
├── ArkanoidGame.js
├── entities/         # Paddle, Ball, Brick
├── systems/          # Input, Collision, Level, Hud, Sound
└── utils/
    └── constants.js  # все числа и цвета в одном месте
```

Разделение на `entities` и `systems` — не для красоты. `entities` — то, что существует в мире (у каждого есть `view` для Pixi, `bounds` для коллизий, `update`). `systems` — то, что происходит между ними. Когда добавлял power-up'ы в планах на будущее — понял, что не придётся лезть в `Ball` и `Paddle`, достаточно дописать систему. Это и есть смысл разделения.

Все константы — размеры, цвета, физика — в `constants.js`. Менять скорость мяча или палитру блоков можно в одном месте, не ища по проекту.

## Использованные подходы

- **Game Loop** — один `ticker` на всю игру, всё обновляется из него.
- **Entity-System** — сущности не знают друг о друге, столкновения считает отдельный класс.
- **State Machine** — пять состояний через `STATE` и `setState()`. Никаких вложенных `if (isPlaying && !isPaused && !isOver)`.
- **Layered Scene** — два контейнера в сцене. Тряска двигает только `world`, HUD при этом неподвижен. Ради этого слои и разделял.
- **Lazy init для звука** — `AudioContext` создаётся при первом действии пользователя, потому что браузеры блокируют автозапуск.

## Что не сделано

- **Один уровень.** Прогрессии по уровням нет, после победы начинается та же сетка.
- **Прогресс не сохраняется** — при перезагрузке страницы счёт обнуляется.
- **Кнопки mute нет** — звуки тихие, но выключить их из интерфейса нельзя.
- **Мобильная версия** — ТЗ просит только десктоп, так что touch не обрабатываю.
- **Тестов нет.** Проверял руками, автотестами не покрывал — на это ушло бы больше времени, чем на саму игру.
- **Сборщика нет.** Importmap и CDN работают, но для продакшена взял бы Vite.
- **Только один монитор.** Если перетащить окно на второй — canvas остаётся того же размера.
